# ログインボーナスのカレンダー表示 V2・V3b の実測

> **この実測の注意（PR 本文に転記できる）**: 測ったのは「未ログインの状態の login_bonus・home を単独起動」したときのデバイス非依存の指標だけです（実サーバーを通した通しは、ローカルのサーバーが旧スキーマで login が 500 のため不可）。最大構成（通常 7＋VIP 7＋報酬 5 行）は V3b の後に測り、下の「V3b 後の指標」に追記した。実機（iPhone X）の 60fps も未測定です。ホームのドロー呼び出しが一時 31 → 28 に減って見えたのは、値ラベルが幅 1 に潰れて文字が描かれていなかった不具合（修正済み）の影響とみられ、修正後の測り直しでは +3（アイコン 3 つぶん）になりました。

`client_design.md` の 7 節（60fps の指標）と 5-6 節（APK 容量 R4）の、V2 時点の実測値。V3b（カレンダー表示・スタンプ）の後に同じ手順で測り直して下に追記した。V3c（ホームの導線・再受け取り）の後にもう一度測り直す。**実機（iPhone X）での 60fps は未確認**（書き出しテンプレートが無く、この環境では測れない）。

## 60fps の指標（R2）

- 手順: `debug/frame_probe.gd` を `--e2e-frame-probe=<秒>`（`debug/e2e_driver.gd`）で起動し、画面が出てから 2 秒間（約 105 フレーム）の `TIME_PROCESS`・ドロー呼び出し・オブジェクト数・ノード数の平均・最大を `E2E_PROBE:` の行に出す。**ヘッドレスでは描画統計が 0 になるので、ウィンドウありの通常起動で測った**（macOS・Metal・Forward Mobile。ヘッドレスのときは行に `render=unavailable(headless)` が付く）
- 測った画面: `login_bonus.tscn` と `home.tscn` を単独で起動（`godot --path . res://contexts/.../xxx.tscn -- --e2e-case=probe --e2e-frame-probe=2`）。**ローカルのサーバーが旧スキーマのまま（login が 500 を返す）で、実サーバーを通した通しの起動ができなかったため、未ログインの状態（ログインボーナスは受取なし・ホームの値は「-」）で測った**。ドロー呼び出し・オブジェクト数・ノード数は端末に依らない指標なので、変更前後の比には使える。`TIME_PROCESS` は開発機の値で、背景動画のデコードに支配されて 21〜41ms とばらつく（絶対値には使わない）
- 変更前の基準（main）と、V2 の後（ホームの値の横のアイコン 3 つを足した状態）:

| 画面 | 状態 | ドロー呼び出し（平均 / 最大） | オブジェクト数 | ノード数 | `TIME_PROCESS` ms（平均。ばらつく） |
| --- | --- | --- | --- | --- | --- |
| ログインボーナス（現行の文字の画面） | 変更前 = V2 後（V2 では変えない） | 12.88 / 13 | 80.2 / 81 | 29 | 24〜33 |
| ホーム | 変更前（3 回） | 30.7 / 31 | 72.3 / 73 | 46 | 27.6〜30.7 |
| ホーム | V2 後（不具合修正後。3 回） | 33.7 / 34 | 75.3 / 76 | 52 | 32.2〜41.2 |

- 読み: ホームはノードが 46 → 52（`ValueRow` 3 つ + `ItemIcon` 3 つ）、ドロー呼び出しは 30.7 → 33.7、オブジェクト数は 72.3 → 75.3 で、いずれも +3（アイコン 3 つ。1 つにつき 1）と直感どおり。`TIME_PROCESS` は動画のデコードに支配されたばらつきの範囲（同じ状態でも 21〜41ms）で、判断には使わない
- 経緯（修正済みの不具合）: 最初の測定（V2 後 27.7 / 69.3）は、値ラベル（`text_overrun_behavior = trim` で最小幅 1）が `ValueRow`（HBox）の中で横に広がらず幅 1 に潰れ、**数値の文字が描かれていなかった状態**で測っていた。変更前より減って見えたのはそのためとみられる（ラベルの文字が描かれない分のドロー呼び出し・オブジェクトが減る）。`size_flags_horizontal = 3` を付けて直し、`home_presenter_test` に幅の検査を足した。アイコンの texture を外した切り分け（24.8 / 66.4）も同じ不具合のある状態での値で、参考にしない
- 最大構成の変更後の値は、下の「V3b 後の指標」を参照

## V3b 後の指標（カレンダー表示・スタンプのアニメーション。FROM_LOGIN のみ）

- 手順: V2 と同じ（ウィンドウあり・macOS・Metal・Forward Mobile、画面が出てから 2 秒、約 105 フレーム）。ログインボーナス画面の最大構成は、サーバー・マスターの配信ファイルが無い環境でも描けるよう、`debug/login_bonus_preview.tscn`（本物の `LoginBonusPresenter` と `GetLoginBonusScreenUseCase` に、偽のマスターと偽の `mst_item` を差し込む debug 専用の画面）を `-- --preview=<名前> --probe=2` で起動して測った。**スタンプのアニメーション（通常 0.3〜0.8 秒・VIP 0.5〜1.0 秒）の最中を含む 2 秒**。ホームは V2 と同じ単独起動（`--e2e-frame-probe=2`）
- 構成: `normal` = 通常 7 日だけ（報酬 1 行）、`both` = 通常 7＋VIP 7（報酬 2 行）、`max` = 通常 7＋VIP 7＋報酬 5 行（設計の最大構成）。各 3 回
- 比較の基準: V2 の「ログインボーナス（現行の文字の画面）」12.88 / 80.2 / 29 とホーム（V2 後）33.7 / 75.3 / 52

| 画面 | ドロー呼び出し（平均 / 最大） | オブジェクト数（平均 / 最大） | ノード数 | `TIME_PROCESS` ms（平均。ばらつく） |
| --- | --- | --- | --- | --- |
| ログインボーナス 文字の画面（V3b。星の行を外した） | 11.9 / 12 | 77.3 / 78 | 38 | 31〜35 |
| ログインボーナス 通常だけ（報酬 1 行） | 62.4 / 63 | 207 / 209 | 128 | 22〜29 |
| ログインボーナス 通常＋VIP（報酬 2 行） | 113.7 / 115 | 379 / 383 | 217 | 21〜31 |
| **ログインボーナス 最大構成（通常 7＋VIP 7＋報酬 5 行）** | **122.6 / 124** | **507 / 512** | **226** | 25〜43 |
| ホーム（V3b 後。V2 から変えていない。3 回） | 33.7〜34.0 / 34 | 75.3〜76.0 / 76 | 52 | 22〜41 |

- 読み: 最大構成は、文字の画面（V2 の基準 12.88 / 80.2）に対してドロー呼び出し **約 9.5 倍**・オブジェクト数 **約 6.3 倍**、ホーム（約 34 / 76）に対して **約 3.6 倍 / 約 6.7 倍**。1 マスあたり ドロー呼び出し 約 7（枠・N 日目・絵・数量・＋n の文字と縁取り、スタンプ）、ノード 約 7。`TIME_PROCESS` は V2 と同じく背景動画のデコードに支配されたばらつき（同じ構成でも 21〜43ms）で、判断に使わない。
- 注意: `normal` → `both` で +51 ドロー呼び出しなのに `max`（報酬 5 行ぶん）は +9 しか増えていないのは、報酬の行がマスよりずっと軽いため（1 行 = 絵と文字の 2 つ）。通常 7 の段 1 つは約 51 ドロー呼び出し。
- **実機（iPhone X）の 60fps は未測定**（書き出しテンプレートが無く、この環境では測れない）。上の比は開発機の描画統計で、ドロー呼び出し 約 123・オブジェクト 約 507 が A11 で 16.6ms に収まるかは実機で確かめるまで分からない。「減っていない」ことは確かめたが、**値が減って見えても実装の効果とは読まない**（V2 で値ラベルが潰れて文字が描かれず、ドロー呼び出しが減って見えた例がある。V3b では文字・絵が描かれていることを画像（`--preview` の撮影）と `login_bonus_layout_test` の幅・高さの検査で確かめてから測った）
- 軽くする余地（設計 7 節の順）: ① 脈動はアニメーションを再生するマスの押印前だけに限定済み ② VIP の開始のずらし（0.5 秒）は実装済み ③ マスの影を使わず、枠は影なしの `StyleBoxFlat` の `Panel` 1 枚。実機で足りないときは、枠（`Panel`）をマス全体の事前に作った絵に替える・「N 日目」と数量を 1 つの `Label` にまとめるなどでノード・ドロー呼び出しを減らす

## APK 容量（R4）

`docs/ASSETS.md` の「アイコン（自作）」の「容量の実測」の表を参照（比較用の 3 点の時点と全 40 点の時点の 2 回）。結果: 全 40 点で SVG 41,792 B・import 後 155,552 B・pck の差 176,660 B で、基準（1MB 以内かつ背景動画 2,028,637 B 以内）を満たす。なお比較用の 3 点の時点の pck の差は、製品用の複製ではなくリポジトリ全体の複製で測った（アイコンあり・なしの差だけを見るので値は同等）。
